# 第一部分：3DGS 讨论收束

## 1.1 核心结论

| 问题 | 结论 |
|------|------|
| 3DGS 是什么 | 数百万个半透明 3D 椭球体的集合，不是传统的多边形模型 |
| 和 FBX/GLB 的区别 | 3DGS = 扫描的"空间快照"（不可编辑单个物体），FBX/GLB = 离散可编辑资产 |
| 在 DireX 中的定位 | **虚拟片场 / 空间参考** — 不是可编辑的 3D 资产 |
| PLY vs 3DGS | 标准 PLY（点云/网格）↔ 3DGS PLY（高斯泼溅）↔ 不同格式，不同用途 |
| 要不要全上 3DGS | 不需要 — 按资产重要性分级：核心场景→3DGS，次要道具→标准PLY，CG角色→FBX/GLB |

## 1.2 浏览器 2GB VRAM 瓶颈

- Chrome 对每个标签页的 GPU 内存预算约 2GB（WebGL 上下文）
- 一个 300 万 splat 的 3DGS 场景自身占 1.5-2GB
- **这是浏览器沙箱架构决定的，不是优化能解决的问题**
- WebGPU 后端可缓解到 4-6GB，但天花板依然存在

## 1.3 解决方案：云端渲染 + 客户端预览

```
┌──────────────────────────────────────────────┐
│                DireX 混合渲染架构              │
│                                              │
│  客户端浏览器（WebGL）         云端 GPU 实例    │
│  ┌──────────────────┐       ┌──────────────┐ │
│  │ FBX/GLB 模型     │       │ 3DGS 场景渲染 │ │
│  │ 骨骼动画         │       │ 高质量快照    │ │
│  │ 简单场景预览     │       │ PLY 点云处理  │ │
│  │ 参数调节         │       │ AI 管线注入   │ │
│  └──────────────────┘       └──────────────┘ │
│         │                          │         │
│         └──── 相机参数/场景指令 ────┘         │
│         ←──── 渲染结果（快照/流）── ─┘         │
└──────────────────────────────────────────────┘
```

## 1.4 云端渲染成本特征

| 操作 | GPU 消耗 | 成本等级 |
|------|---------|---------|
| 上传扫描数据 | 0（纯 I/O） | 零 |
| 旋转/移动视角（客户端） | 0 | 零 |
| **点击预览**（云端单帧渲染） | ~5ms（3DGS 单帧） | **≈ 零**（$0.000005/次） |
| 连续 30fps 云流 | 150ms/秒 | $0.10-0.18/用户·小时 |
| 场景空闲 | 0 | 零 |

> **佐证**: IEEE 2025 基准测试 — 3DGS 在 A100 上单帧渲染平均 4.53ms（Chair 6.16ms, Hotdog 2.74ms）。在 RTX 3060 Ti 上 11-33ms/帧（Vulkan 跨平台实现）。

## 1.5 产品路线

| 阶段 | 内容 | 客户端 | 云端 |
|------|------|--------|------|
| **P0** | 标准 PLY 点云导入 → 显示 → 旋转查看 | ✅ | — |
| **P1** | 3DGS .ply / .ksplat 导入 → 客户端低精度预览 | 降采样 50 万 splats | 完整精度场景驻留 |
| **P2** | 选角度 → 云端高质量快照 → 注入 AI 管线 | 参数控制 | 按需渲染单帧 |
| **P3** | CG 资产叠加（FBX 角色放在 3DGS 场景里） | 混合渲染 | 云端最终合成 |

## 1.6 比例尺问题

- **不做标尺数字**（违反"无需学习成本"原则）
- 用**视觉参照**替代：场景中自动放置人类剪影（silhouette）作为比例基线
- 导入 3DGS 场景时自动检测物理尺寸 → 自动缩放 → 用户只看不调
- `RENDER_DIST=50` / `far=80` 在导入大场景时自动拉远，用户无感知

## 2.5 成本优化策略（所有方案通用）

### 策略一：GPU 自动休眠

```
用户最后请求 → 5 分钟无操作 → GPU 实例自动关机
                    ↓
新请求到达 → CPU 实例收到 → 触发 GPU 实例开机
                    ↓
          30-60 秒冷启动 → GPU 就绪 → 处理请求
```

- 省 50%-70% GPU 费用（夜间/非活跃时段不付费）
- 代价：冷启动 30-60 秒延迟（首次快照需等待，可显示"预热中"）

### 策略二：快照缓存

```
用户 A 在某角度请求快照 → 渲染 → 缓存 {场景ID, 相机参数} → 结果
用户 B 在相近角度请求   → 直接返回缓存（不重新渲染）
用户 A 再次相同角度     → 缓存命中（不重新渲染）
```

- 高频使用场景下可减少 40%-60% 渲染量
- 代价：缓存存储费用（可设 TTL 自动过期）

### 策略三：阶梯式质量

```
快速预览（编辑中）:  512px,  低 splat 密度 → 渲染快（2ms）
确认帧（定稿时）:    1024px, 中 splat 密度 → 渲染中（4ms）
最终出图:            2048px, 全精度      → 渲染慢（10ms）
```

- 用户编辑时 80% 的请求是"快速预览"，消耗最小
- 只有最终导出时上全精度

### 策略四：混合渲染（优先客户端）

```
场景 < 2GB 浏览器 VRAM → 客户端渲染（云端不花钱）
场景 > 2GB              → 自动切换到云端渲染
```

- "免费"覆盖大部分中小场景
- 云端只在真正需要时才介入

## 2.6 推荐方案

### 短期（开发 + 内测）：阿里云

- ✅ 国内网络最优（用户无感知延迟）
- ✅ A10 GPU 可用性稳定
- ✅ 新用户活动 ¥1.90/时 + 抢占实例 ¥0.85/时
- ✅ 按量计费灵活，不超预算
- **预估月成本：¥100-1,800**（开发→内测）

### 中期（正式上线）：阿里云为主 + GCP 海外补位

- 国内用户 → 阿里云（低延迟）
- 海外用户 → GCP g2-standard-4 ($0.70/hr)（性价比最高）
- 双区域 + Cloudflare 全球加速

### 不推荐

- **腾讯云**：GPU 产品线缺乏 24GB 中间档（只有 16GB T4 和 40GB A100），A100 价格 ¥20/时严重过剩
- **AWS 中国区**：GPU 实例可用区受限，A10G 库存不稳定
