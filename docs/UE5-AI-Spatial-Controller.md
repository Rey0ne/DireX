## 一、市场信息差：大多数人对 UE5 的认知是错的

### 1.1 普遍认知

> "UE5 = 游戏引擎，做 3A 大作用的，和 AI 生图没关系。"

**这是错的。** 迪士尼用 UE5 拍《曼达洛人》已经五年了——UE5 是一个**实时可视化引擎**，游戏只是它的一个应用场景。它的另外两个核心场景是：

- **虚拟制片（Virtual Production）**：LED 棚拍，实时渲染 3D 场景，摄影机直接拍
- **场景地编（Level Design / Layout）**：搭建空间、布置灯光、放置摄影机

这两个场景和 AI 图像生成有**直接的、强耦合的**交集，但目前市场几乎没有人在做这个连接。

## 二、技术论证：为什么 UE5 + AI 能显著提升生成命中率

### 2.1 纯 Prompt 生图的根本瓶颈

当用户写一段 Prompt 时，AI 需要同时"猜测"以下所有维度：

| 维度 | 用户 Prompt | AI 猜测难度 |
|------|-----------|-----------|
| **空间构图** | "一个人站在房间里" | 极高 — 房间多大？人站哪里？ |
| **透视/景深** | 几乎没有描述 | 极高 — 仰拍？俯拍？焦距？ |
| **灯光方向** | "温暖的阳光" | 极高 — 从哪边照？多强？色温？ |
| **物体遮挡** | 无描述 | 极高 — 前景有什么挡住？ |
| **比例关系** | "远处有座山" | 高 — 到底多远？多大？ |
| **材质质感** | "金属质感" | 中 — 镜面反射？磨砂？氧化？ |

**每一个未指定的维度都是一次随机抽奖。** 10 个维度 × 每个维度 3-10 种可能 = 数万到数百万种组合。用户想要的"那一张"，命中率自然只有 10-30%。

这不是 AI 能力不够，是**控制信号不够精确**。

### 2.2 UE5 如何补上控制信号

UE5 在每个维度的作用：

```
┌─────────────────────────────────────────────────────────┐
│                   UE5 空间控制器                         │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │ 场景搭建  │  │ 灯光系统  │  │ 摄影机    │              │
│  │          │  │          │  │          │              │
│  │ • 物件位置│  │ • 方向    │  │ • 机位    │              │
│  │ • 遮挡关系│  │ • 强度    │  │ • 焦距    │              │
│  │ • 比例   │  │ • 色温    │  │ • 景深    │              │
│  │ • 材质   │  │ • 阴影    │  │ • 构图    │              │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘              │
│       │              │              │                    │
│       └──────────────┼──────────────┘                    │
│                      │                                   │
│              ┌───────▼────────┐                          │
│              │ 渲染低精度快照  │                          │
│              │ 512-1024px 足够│                          │
│              └───────┬────────┘                          │
│                      │                                   │
│                      ▼                                   │
│              ┌──────────────────┐                        │
│              │ 4-Agent Pipeline │                        │
│              │ + 空间控制信号    │                        │
│              └──────────────────┘                        │
└─────────────────────────────────────────────────────────┘
```

**核心逻辑**：AI 不再需要"猜"空间关系。粗糙 3D 场景提供了确定性的构图 → 透视 → 遮挡 → 灯光 → 比例关系。AI 只需要在这些正确的基础上"上色"和"加细节"，而不是从头创造一切。

### 2.3 和 ControlNet 的对比

ControlNet 是目前 AI 生图控制的主流方案。但它有一个根本缺陷：

| | ControlNet | UE5 空间控制器 |
|------|-----------|--------------|
| 控制源 | 需要**已有**参考图 | **凭空创造**场景 |
| 深度图 | 从参考图提取 | 直接渲染（物理精确） |
| 姿态 | 需要真人照片 | 绑定骨骼动画 |
| 线稿 | 需要手绘 | 渲染边缘检测 |
| 调整成本 | 重新找/重新画 | UE5 场景里拖拽 |
| 灯光控制 | 无法独立控制 | 独立灯光系统 |
| 摄影机控制 | 无 | 物理摄影机系统 |
| **迭代效率** | **低（换个角度要重画）** | **高（挪摄影机一秒钟）** |

**ControlNet 本质上是"用已有信号约束 AI"。UE5 方案是"凭空制造最精确的信号"。**

从信息论的角度：
- 纯 Prompt：给 AI 的信息量 ≈ 几百 tokens
- ControlNet：给 AI 的信息量 ≈ 一张控制图的像素信息
- UE5 快照：给 AI 的信息量 ≈ 一张物理精确的渲染图 + **隐含的所有空间约束**

### 2.4 命中率量化估算

| 方案 | 纯 Prompt | Prompt+参考图 | ControlNet | UE5快照+Agent |
|------|----------|-------------|-----------|-------------|
| 构图准确率 | ~30% | ~50% | ~70% | **~90%+** |
| 灯光准确率 | ~20% | ~40% | ~50% | **~90%+** |
| 透视准确率 | ~25% | ~45% | ~65% | **~95%+** |
| 风格匹配率 | ~50% | ~70% | ~70% | **~85%+** |
| **综合首图命中** | **~10%** | **~25%** | **~40%** | **~75%+** |

这些数字是估算的，但逻辑基础是坚实的：**AI 在正确空间约束下，失败的维度大幅减少。**

## 三、产品逻辑：TapNow 在这个体系中的角色

### 3.1 不是在画布里"跑 UE5"

**关键定位纠正**：UE5 节点不是要替代 UE5 编辑器，不是要做云游戏，不是要让用户在浏览器里操作 UE5。

**UE5 节点是一个"空间参数调控器"：**

```
用户操作（在 TapNow 画布内）：
  1. 新建 UE5 节点
  2. 选择一个预设 3D 模板（室内/户外/棚拍/概念）
  3. 拖拽调整几个参数：机位角度、焦距、灯光方向、主体位置
  4. 点击"生成快照" → UE5 远端渲染一帧 512px 参考图
  5. 快照 + ShotNode 元数据 → 4-Agent Pipeline
  6. AI 生成高质量成图
```

用户不需要：
- 安装 UE5
- 会建模
- 会 PBR 材质
- 理解 Nanite/Lumen
- 知道什么是 Pixel Streaming

用户只需要：**拖动几个滑块 / 选择几个预设**。复杂的东西（UE5 场景搭建、光照烘焙、材质设置）全部**预设化**。

```
│  │ 模板   │  │ 模板   │  │ 模板   │               │
│  └───┬────┘  └───┬────┘  └───┬────┘               │

│     ┌─────────────▼─────────────┐                   │
│     │   参数注入（API 调用）      │                   │
│     │   • 摄影机位置/角度        │                   │
│     │   • 焦距/光圈             │                   │
│     │   • 灯光参数              │                   │
│     │   • 场景元素显隐          │                   │
│     └─────────────┬─────────────┘                   │
│                   │                                 │
│     ┌─────────────▼─────────────┐                   │
│     │   UE5 渲染单帧 (512px)     │  ← GPU 实例       │
│     │   ~1-3 秒 / 帧            │  按需启动          │
│     └─────────────┬─────────────┘                   │
│                   │                                 │
│                   ▼                                 │
│         渲染快照 → 返回给用户                         │
└──────────────────────────────────────────────────┘
```

**成本优势**：512px 低画质渲染，一张图 1-3 秒。一台 T4 GPU 可以串行服务每秒 1 个请求。如果用户平均每 30 秒请求一次快照，一台 GPU 可以同时服务 30 个活跃用户。不需要独占 GPU。

## 四、商业逻辑：这个故事的估值溢价

### 4.1 市场对比

目前市面上没有"UE5空间控制 + AI生成"的整合产品。最近似的结构：

| 产品 | 解决了什么 | 未解决什么 |
|------|-----------|-----------|
| **ComfyUI + ControlNet** | 精确控制，社区生态强 | 需要先有控制图，不能凭空造场景 |
| **Krea.ai** | 实时画布+AI | 没有 3D 空间信息，仍然是 2D 画布 |
| **Leonardo.ai** | AI 生图平台 | 纯 2D，没有 3D 空间控制 |
| **Runway** | AI 视频 | 有少量 3D 元素但不是核心 |
| **Cuebric (好莱坞)** | UE5 + AI 背景生成 | 专业影视级，面向大制片厂 |

**TapNow 的卡位**：在 ComfyUI 的自由度、Krea 的易用度、Cuebric 的专业度之间，找到一个**"足够专业但不难用"**的中间地带。

### 4.2 目标用户画像

```
主要用户：AI 内容创作者 + 影视/游戏前期团队

具体来说：
  • 独立影视制作人 — 需要快速出分镜/概念图，没有专业 3D 团队
  • 游戏概念设计师 — 需要快速迭代场景构图，以前要自己建模
  • AI 艺术创作者 — 想提升出图命中率，被随机性困扰
  • 广告创意团队 — 需要快速产出高质量视觉提案
  • 动漫/漫画前制 — 需要确定场景空间关系，多镜头一致性
```

中国市场这只群体不小：B站 AI 绘画教程单期播放量数十万，ComfyUI 中文社区活跃度极高，影视/游戏行业正处于 AI 焦虑期。

### 4.3 防御壁垒分析

| 壁垒层级 | 内容 | 可复制性 |
|---------|------|---------|
| **L1: UX 层** | ReactFlow 画布、节点系统 | 低壁垒，几周可抄 |
| **L2: Agent 层** | 4-Agent Pipeline | 中低壁垒，Prompt Engineering 可复制 |
| **L3: 数据层** | 大量 UE5 场景模板、参数预设 | **中高壁垒**，需要 UE5 专业能力 + 时间积累 |
| **L4: 整合层** | UE5 → Agent → 多模型生成的完整管线 | **高壁垒**，需要跨界能力 |
| **L5: 认知层** | "UE5 ≠ 游戏引擎"的市场教育 | **最高壁垒**，先发者定义品类 |

**核心防御不是代码，是"UE5 模板资产库"和"品类定义者"的心智占位。**

### 4.4 估值逻辑

```
阶段 1：技术验证（当前 → 2个月后）
  └─ UE5 云端单帧渲染跑通，管线上线
  └─ 3-5 个场景模板可用
  └─ 内测用户 50-100 人，验证命中率提升
  └─ 估值：$1M - 3M（天使轮，概念验证）

阶段 2：产品 PMF（3-8个月后）
  └─ UE5 模板库 ≥ 20 个场景
  └─ DAU 500+，生成命中率数据可对外展示
  └─ 付费转化 ≥ 2%
  └─ 估值：$5M - 12M（Pre-A / A 轮）

阶段 3：品类定义（12-18个月后）
  └─ "AI 空间控制"成为独立品类关键词
  └─ UE5 模板市场（用户/第三方可上架）
  └─ 行业标杆案例（影视/游戏公司使用）
  └─ 估值：$20M - 50M（A / A+ 轮）

阶段 4：平台化（2年+）
  └─ 除了 UE5，接入更多 3D 引擎（Blender, C4D）
  └─ 自有轻量 3D 编辑器（用 Three.js 做局部微调）
  └─ 资产市场 + 工作流市场
  └─ 估值：$100M+（B 轮+，平台型定价）
```
